# 03 数据库与数据管理

## 存储

PostgreSQL 保存结构化数据，S3 兼容对象存储保存用户上传的原 PDF；页图和裁剪图非首版必需。所有表含 `tenant_id`、`created_at`；业务主键 UUIDv7，示例中的短 ID 仅便于阅读。正式数据只由审核通过的事务写入。

| 表 | 关键列与约束 |
|---|---|
| `companies` | id, hkex_code, name, industry_code; `(tenant_id,hkex_code)` 唯一 |
| `reports` | id, company_id, report_year, revision, sha256, object_uri, page_count, published_at; `(tenant_id,sha256)` 唯一 |
| `metric_definitions` | metric_id, version, name, value_kind, canonical_unit, status; `(metric_id,version)` 唯一 |
| `evidence` | id, report_id, page, printed_page, exact_text, context_text, source_type, bbox_json, crop_uri, locator_method |
| `extraction_candidates` | id, report_id, raw_value_text, raw_text, raw_unit, data_year, period, boundary_json, metric_id nullable, metric_version nullable, classification_status, classification_reason, alternatives_json, confidence, ambiguity_json, skill_versions_json, supersedes_id, model_call_id |
| `candidate_evidence` | candidate_id, evidence_id; 复合主键 |
| `audits` | id, candidate_id, status, checks_json, reason, issues_json, pdf_evidence_json, reviewer_type, reviewer_id nullable, supersedes_id |
| `review_cases` | id, audit_id, status, assigned_to, row_version, resolved_at |
| `official_facts` | id, report_id, candidate_id, audit_id, company_id, metric_id, metric_version, data_year, period, boundary_json, raw_value_text, raw_unit, normalized_value numeric nullable, normalized_unit, status, supersedes_id |
| `calculation_results` | id, formula_id, formula_version, input_fact_ids_json, parameters_json, result_value, unit, status |
| `tasks` | id, report_id nullable, stage, status, attempt, checkpoint_json, idempotency_key |
| `agent_runs` | id, task_id, agent_name, started_at, ended_at, status, prompt_version, skill_digest |
| `model_calls` / `tool_calls` | id, run_id, request_ref, response_ref, usage_json, latency_ms, status, error_code |

正式事实允许同公司、同指标、同数据年存在多条：报告版本、边界、期间或口径不同均保留。仅 `(tenant_id,audit_id)` 唯一以防重复提交。`supersedes_id` 链表达更正，`status=ACTIVE|SUPERSEDED`；查询默认 ACTIVE，同时可按报告版本回溯。删除报告需先检查引用，生产只做逻辑撤销。

## 保存事务

`publish_audited_fact(audit_id)->OfficialFact`：锁定审核行；检查 `PASS` 或人工批准、候选归类、证据完整、报告哈希；Python 单位转换并写入标准值；插入正式事实和 outbox 事件；提交后通知索引更新。幂等重复调用返回同一 fact_id。

## 查询

`get_company_metric_data(company_id, metric_id, start_year, end_year, boundary_filter=None, as_of=None)->list[FactView]`。`FactView` 必含 report_id、fact_id、audit_id、evidence_ids、raw/normalized 值、单位、边界与版本。行业查询先按企业当前行业成员关系筛选，再只取审核通过且 ACTIVE 数据；统计须给样本量、缺失数及可比口径筛选条件。不能用缺失值补零。

索引：`official_facts(tenant_id,company_id,metric_id,data_year)`、`reports(company_id,report_year)`、`review_cases(status)`、`tasks(status,stage)`；大规模按 tenant/report_year 分区并通过迁移验证。
